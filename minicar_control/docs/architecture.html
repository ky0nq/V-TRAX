무선 미니카 제어 아키텍처

INTERFACE ARCHITECTURE — WIRELESS MINI-CAR CONTROL (ICD v0.2)

무선 미니카 제어 시스템 아키텍처

확정된 ICD v0.2를 기준으로 다시 그렸다. 시스템은 Sensor → Zybo → ESP32 #1(무선 브릿지) → ESP32 #2(차량 제어) → L298N → TT Motor ×4 로 이어지는 단일 파이프라인이며, IF-01~IF-06 여섯 개 인터페이스로 경계가 정의된다. Zybo가 만든 8-byte CommandPacket은 변환 없이 UART와 ESP-NOW를 그대로 통과하고, Vehicle Controller는 통신 방식과 무관하게 DriverCommand 구조체만 입력으로 받는다. Sensor부터 Motor까지 전 구간을 실물로 통합해 동작을 확인했다.

모듈별 책임

Zybo는 “무엇을 할 것인가”만 결정한다(Measurement 해석 → Command 생성). ESP32 #1은 “명령을 전달한다”에 한정되며 SOF/CRC/범위 검증 외의 판단은 하지 않는다. ESP32 #2는 “그 명령을 어떻게 차량 동작으로 만들 것인가”를 담당하며 수신 단계에서 발신 MAC과 CRC를 다시 검증해 신뢰할 수 없는 Packet을 걸러낸다. L298N은 “계산된 출력대로 실제 전력을 공급한다”만 수행한다. 각 모듈이 자신의 책임 밖 판단(예: ESP32 #1의 차량 동역학 계산, L298N의 제어 판단)을 하지 않도록 경계를 지키는 것이 이 ICD의 핵심이다.

확정 / 미확정

Command 범위(Steering ±90°/10°, Accel·Brake 0~5), 8-byte Packet 구조, UART(115200/8-N-1/100Hz), ESP-NOW(Ch.1 명시적 고정, 8-byte, 발신 MAC 필터링), ESP32 #1 MAC(B0:3F:D3:75:17:50)과 ESP32 #2 MAC(B0:3F:D3:64:04:14), ESP32 #1측 UART 핀(RX16/TX17), Zybo측 UART0(MIO14/15)·I2C1(MIO12/13), ESP32 #2 제어 주기(50Hz)와 Failsafe(300ms), L298N 핀 배정(25·26·27 / 32·14·13)은 확정되었고, Sensor부터 Motor까지 전 구간을 실물로 통합해 동작을 확인했다. 남은 TBD는 FSR 전압 범위와 ADC Resolution, Accel/Brake 임계값(현재 값은 임시), Steering 보정, 최종 모터 전원과 튜닝 파라미터다.
