무선 미니카 제어 아키텍처

INTERFACE ARCHITECTURE — WIRELESS MINI-CAR CONTROL (ICD v0.3)

무선 미니카 제어 시스템 아키텍처

센서 취득이 Zybo에서 ESP32 #3로 분리되면서 4노드 구조가 되었다. 두 종류의 8-byte 패킷이 파이프라인을 돈다 — SensorPacket(A5 5A)은 페달 원시값을 Zybo로 올리고, CommandPacket(AA 55)은 Zybo가 만든 주행 명령을 차량으로 내린다. ESP32 #1은 양방향 허브로서 두 패킷 모두를 검증만 하고 재가공 없이 통과시키며, 두 흐름은 같은 UART 페어의 서로 반대 방향을 쓴다. SOF가 달라 스트림이 섞이지 않는다. Sensor부터 Motor까지 전 구간을 실물로 통합해 동작을 확인했다.

모듈별 책임

ESP32 #3는 “측정해서 올린다”만 한다 — 임계값을 모르고 Level로도 바꾸지 않는다. 원시 counts를 그대로 보내는 이유는 판단 지점을 한 곳에 모으기 위해서다. ESP32 #1은 “전달한다”에 한정되며, 두 방향 모두 SOF/CRC/범위 검증 외의 판단을 하지 않고 Payload를 건드리지 않는다. Zybo는 “무엇을 할 것인가”를 결정한다 — 센서 해석, PC 입력 병합, 타임아웃 감시, Command 생성이 전부 여기 모여 있다. ESP32 #2는 “그 명령을 어떻게 차량 동작으로 만들 것인가”를 담당하고, L298N은 “계산된 출력대로 전력을 공급한다”만 수행한다. 각 모듈이 자기 책임 밖 판단을 하지 않도록 경계를 지키는 것이 이 ICD의 핵심이다.

v0.2 → v0.3 변경

센서 취득이 Zybo의 I2C1(MIO12/13)에서 ESP32 #3로 이동했다. Zybo는 더 이상 I2C를 사용하지 않으며, ADS1115는 ESP32 #3에 GPIO21/22로 연결된다. 이에 따라 SensorPacket(A5 5A)이 새로 정의되었고, Zybo↔ESP32 #1 UART는 단방향에서 양방향이 되었다. 인터페이스 번호도 IF-01~06에서 IF-01~09로 재편되었다. Command 송신률은 v0.2의 100Hz에서 50Hz로 되돌렸다 — 센서가 50Hz로 도착하므로 그보다 빠른 명령 생성은 같은 샘플을 다시 보내는 것에 불과하다. 새 무선 홉이 생긴 만큼 Sensor Link 200ms 타임아웃이 추가되었고, 모든 타임아웃은 루프 횟수가 아닌 벽시계 기준으로 통일했다.

확정 / 미확정

Command 범위(Steering ±90°/10°, Accel·Brake 0~5), 두 패킷 구조와 CRC-8, UART(115200/8-N-1, 양방향), ESP-NOW(Ch.1 명시적 고정, 발신 MAC 필터링), 세 ESP32의 MAC, Zybo UART0 MIO14/15(Pmod JF9/JF10)과 UART1 MIO48/49, ESP32 #3 I2C 핀(GPIO21/22), 제어 주기(Zybo·#2·#3 모두 50Hz), 세 타임아웃(200/500/300ms), 센서 검증 한계(범위 −1000~26400, 변화율 15000/샘플), L298N 핀 배정(25·26·27 / 32·14·13)은 확정되었고, Sensor부터 Motor까지 전 구간을 실물로 통합해 동작을 확인했다. 남은 TBD는 FSR 분압 회로와 전압 범위, Accel/Brake 임계값(현재 값은 임시), Steering 보정, 최종 모터 전원과 튜닝 파라미터다.
